## 3. `Day1_Morning_Demo.ipynb` - ทฤษฎีที่รันได้จริง

**เป้าหมาย:** ทำให้ทุกตัวอย่างบนสไลด์ช่วงเช้ากลายเป็นโค้ดที่รันแล้วเห็นตัวเลขจริง ไม่ใช่แค่ดูผ่านตา

**ต้องการแค่:** `numpy` + `matplotlib` ไม่ต้องใช้ GPU รันจบทั้งไฟล์ในไม่กี่วินาที

### 3.1 Perceptron คำนวณด้วยมือ (ขั้นที่ 1.1–1.2 / เซลล์ 6–10)

นิยาม ReLU ด้วย `max(0, z)` แล้วคำนวณหน่วยประสาทหนึ่งหน่วยตามสมการ

```
z = (x₁·w₁) + (x₂·w₂) + b
```

ใช้ค่าจากสไลด์ `x = (2, 3)`, `w = (0.5, -1.0)`, `b = 1.0` ได้ `z = -1.0` → `ReLU(z) = 0` แปลว่าหน่วยนี้**ไม่ส่งสัญญาณออกไป**

จากนั้นขั้นที่ 1.2 เปลี่ยน `w2` จาก `-1.0` เป็น `-0.2` ได้ `z = 1.4` → `ReLU(z) = 1.4` หน่วยเริ่มส่งสัญญาณ - แสดงให้เห็นตรง ๆ ว่า weight คือสิ่งที่กำหนดว่าหน่วยจะ "ติด" หรือ "ไม่ติด"

### 3.2 ทำไมต้องมี activation (ขั้นที่ 2.1–2.2 / เซลล์ 11–16)

**พิสูจน์ด้วยตัวเลข:** เอาชั้นเชิงเส้นสองชั้นมาต่อกัน `y₁ = 2x + 1` แล้ว `y₂ = 3y₁ - 4` เทียบกับชั้นเดียว `y = 6x - 1` แล้วยืนยันด้วย `np.array_equal` ว่าได้ผลเท่ากันทุกค่า

> ข้อสรุป: การซ้อนชั้นเชิงเส้นโดยไม่มี activation ยุบเหลือชั้นเดียวเสมอ การเพิ่มชั้นจึงไม่มีประโยชน์

**ดูด้วยภาพ:** สร้างข้อมูลสังเคราะห์รูปแบบ XOR (กลุ่ม 0 อยู่มุมล่างซ้าย + บนขวา, กลุ่ม 1 อยู่มุมบนซ้าย + ล่างขวา) แล้วลากเส้นตรงหนึ่งเส้นทับ ให้เห็นว่าเส้นตรงเส้นเดียวแบ่งไม่ได้ ต้องอาศัยความไม่เป็นเชิงเส้น

### 3.3 หน้าตาของ activation function (เซลล์ 17–18)

พล็อต ReLU กับ Sigmoid บนช่วง `z ∈ [-5, 5]` เทียบกันสองแผง

- **ReLU** - ค่าติดลบกลายเป็น 0 ค่าบวกผ่านไปตรง ๆ ใช้ในชั้นซ่อน
- **Sigmoid** - บีบทุกค่าให้อยู่ระหว่าง 0 ถึง 1 ใช้ตอนทายสองทาง

### 3.4 Softmax (ขั้นที่ 4.1–4.2 / เซลล์ 19–23)

เขียน `softmax()` เองพร้อมเทคนิค **ลบค่าสูงสุดออกก่อนเข้า `exp`** เพื่อกันเลขล้น (numerical overflow) จากนั้นแปลงคะแนนดิบ `[2.0, 1.0, 0.1]` เป็นความน่าจะเป็น `[0.66, 0.24, 0.10]` ตรงตามสไลด์ ตรวจว่าผลรวมเท่ากับ 1 เสมอ แล้วแสดงเป็นกราฟแท่งพร้อมป้ายตัวเลขบนแท่ง

### 3.5 Crossentropy (ขั้นที่ 5.1–5.2 / เซลล์ 24–28)

```
loss = -ln(ความน่าจะเป็นของคลาสที่ถูกต้อง)
```

คำนวณสามกรณีตามสไลด์ - ให้ความน่าจะเป็นคลาสถูก 0.90 / 0.50 / 0.10 ได้ loss 0.11 / 0.69 / 2.30 ตามลำดับ แล้ววาดเส้น loss เทียบความมั่นใจบนช่วง `p ∈ [0.01, 1.0]` ให้เห็นว่าเส้นพุ่งขึ้นสูงมากเมื่อโมเดลมั่นใจผิด

### 3.6 Gradient descent (ขั้นที่ 6.1–6.2 / เซลล์ 29–34)

ใช้ฟังก์ชันชามง่ายที่สุด `loss = w²` ซึ่งมีอนุพันธ์ `2w` และจุดต่ำสุดที่ `w = 0`

เริ่มจาก `w = 8.0`, `learning_rate = 0.1` แล้ววนลูป 15 ก้าวตามกฎ

```python
w = w - learning_rate * gradient(w)
```

เก็บเส้นทางไว้ใน `history` แล้ววาดเป็นลูกบอลกลิ้งลงชาม

**ลองเล่น:** เซลล์ 34 ชวนให้กลับไปแก้ `learning_rate` ใน **ขั้นที่ 6.1 (เซลล์ 31)** เป็น `0.9` (ใหญ่ไป - ค่าแกว่ง) หรือ `0.01` (เล็กไป - เดินไม่ถึงจุดต่ำสุดใน 15 ก้าว) แล้วรันเซลล์ 31 กับ 33 ใหม่

### 3.7 Epoch / Batch / Step (ขั้นที่ 7.1–7.2 / เซลล์ 35–39)

คำนวณจากตัวเลขจริง: ข้อมูล 60,000 ภาพ, batch size 32 → 1 epoch = 1,875 steps → ฝึก 10 epochs = ปรับพารามิเตอร์ 18,750 ครั้ง จากนั้นทำตารางเทียบ batch size 16/32/64/128/256 ให้เห็นว่า batch ใหญ่ขึ้น จำนวน step ต่อ epoch น้อยลง

### 3.8 สะพานเชื่อมสู่ช่วงบ่าย (เซลล์ 40)

| แนวคิดช่วงเช้า | กลายเป็นอะไรใน Keras |
|---|---|
| perceptron | `layers.Dense` |
| activation | `activation='relu'` |
| gradient descent | `optimizer='adam'` |
| crossentropy | `loss='sparse_categorical_crossentropy'` |

### ส่วนที่ 1 - MLP บน Fashion-MNIST (เซลล์ 4–21)

ชุดข้อมูล: ภาพเสื้อผ้าขาวดำ 28×28 พิกเซล 10 ประเภท - ฝึก 60,000 ภาพ ทดสอบ 10,000 ภาพ

| ขั้น | เนื้อหา |
|---|---|
| 1.1 | `keras.datasets.fashion_mnist.load_data()` ดาวน์โหลดครั้งเดียวแล้ว cache ไว้ที่ `~/.keras/datasets/` |
| 1.2 | **ดูภาพจริงก่อนเสมอ** - พล็อต 10 ภาพแรกพร้อมป้ายคลาส เพื่อยืนยันว่าภาพกับป้ายตรงกัน |
| 1.3 | Normalization - หารด้วย 255 ให้พิกเซลอยู่ในช่วง 0–1 ช่วยให้ gradient descent เสถียร |
| 1.4 | สร้างโมเดล: `Flatten` → `Dense(128, relu)` → `Dense(10, softmax)` |
| 1.5 | compile: `adam` + `sparse_categorical_crossentropy` + `accuracy` |
| 1.6 | fit: `epochs=10`, `batch_size=32`, `validation_split=0.1` |
| 1.7 | นิยาม `plot_history()` พล็อต loss/accuracy ของ train เทียบ validation (ใช้ซ้ำทั้งไฟล์) |
| 1.8 | `evaluate` บน test set เก็บ `mlp_acc` และ `mlp_params` ไว้เทียบกับ CNN |

**จุดที่ให้สังเกต:**
- ชั้น `Dense` แรกมีพารามิเตอร์ `(784 × 128) + 128 = 100,480` รวมทั้งโมเดล **101,770** - จำเลขนี้ไว้เทียบกับ CNN
- ใน loss curve ให้ดูว่าเส้น train กับ validation เริ่มถ่างออกเมื่อไร นั่นคือจุดที่เริ่ม overfitting
- ใช้ `sparse_categorical_crossentropy` เพราะป้าย `y` เป็นเลขจำนวนเต็ม 0–9 ไม่ใช่ one-hot
- เซลล์ 1.3 แก้ค่า `x_train` ทับตัวเดิม ถ้าเผลอรันซ้ำสองครั้งจะกลายเป็นหารด้วย 255 สองรอบ ให้ Restart & Run All เมื่อไม่แน่ใจ

### ส่วนที่ 2 - CNN บนข้อมูลเดียวกัน (เซลล์ 22–36)

แก้โจทย์เดิมด้วยสถาปัตยกรรมที่ออกแบบมาสำหรับภาพโดยเฉพาะ แล้วเทียบผลแบบตัวต่อตัว

| ขั้น | เนื้อหา |
|---|---|
| 2.1 | เพิ่มมิติช่องสีจาก `(28, 28)` เป็น `(28, 28, 1)` ด้วย `np.newaxis` เพราะ CNN ต้องการ (สูง, กว้าง, ช่องสี) |
| 2.2 | สร้าง CNN: `Conv2D(32) → MaxPool → Conv2D(64) → MaxPool → Flatten → Dense(64) → Dense(10)` |
| 2.3 | compile + fit - **โค้ดเหมือน MLP ทุกตัวอักษร** เปลี่ยนแค่ข้อมูลเป็น `x_train_cnn` |
| 2.4 | เทียบ accuracy และจำนวนพารามิเตอร์กับ MLP เป็นตาราง |
| 2.5 | Confusion matrix ด้วย `sklearn` |

**จุดที่ให้สังเกต:**
- ในคอลัมน์ Output Shape ของ `summary()` ภาพหดทีละชั้น: `28 → 26` (Conv ตัดขอบ) `→ 13` (Pool ย่อครึ่ง) `→ 11` (Conv) `→ 5` (Pool) ซึ่งตรงกับเรื่อง padding และ stride ที่เรียนตอนเช้า
- จำนวน filter เพิ่มจาก 32 เป็น 64 เมื่อชั้นลึกขึ้น - เป็นแบบแผนมาตรฐาน
- CNN มีพารามิเตอร์ **121,930** เทียบกับ MLP **101,770** คือมากกว่าประมาณ 20% แต่มักได้ accuracy สูงกว่าอย่างเห็นได้ชัด เพราะ Conv layer ใช้ประโยชน์จากโครงสร้างเชิงพื้นที่ของภาพ ไม่ใช่เพราะมีพารามิเตอร์มากกว่า
- ใน confusion matrix คลาสที่มักถูกสับสนคือ **Shirt / Pullover / Coat / T-shirt** เพราะรูปทรงคล้ายกันมากในภาพขาวดำขนาดเล็ก
- ส่วนนี้ฝึก 10 epochs บน CPU ใช้เวลาหลายนาที (นานกว่า MLP พอสมควร) ถ้าเวลาจำกัดในห้องเรียน ลดเป็น `epochs=3` ก็ยังเห็นแนวโน้มเทียบกับ MLP ได้

### ส่วนที่ 3 - Transfer Learning บนรูปอาหาร (เซลล์ 37–54)

ก้าวจากภาพขาวดำเล็ก ๆ ไปสู่ภาพสีจริง และจากการฝึกใหม่จากศูนย์ไปสู่การยืมความรู้จากโมเดลสำเร็จรูป

ชุดข้อมูล: **pizza / steak / sushi** 3 คลาส ดาวน์โหลดอัตโนมัติจาก repo ของ mrdbourke

| ชุด | จำนวนภาพ | ต่อคลาส |
|---|---|---|
| train | 225 | 75 |
| test | 75 | 25 |

ข้อมูลน้อยมาก - นี่คือประเด็นทั้งหมดของส่วนนี้ ถ้าฝึกใหม่จากศูนย์ด้วยภาพเท่านี้จะไม่มีทางได้ผลดี แต่ transfer learning ทำได้

> ⚠️ ส่วนนี้ควรเปิด GPU

| ขั้น | เนื้อหา |
|---|---|
| 3.1 | `keras.utils.get_file(..., extract=True)` ดาวน์โหลด zip แล้วแตกไฟล์ให้อัตโนมัติ |
| 3.2 | `image_dataset_from_directory` อ่านภาพจากโฟลเดอร์ ใช้ชื่อโฟลเดอร์ย่อยเป็นป้ายคลาส ปรับขนาดเป็น 224×224 |
| 3.3 | ดูตัวอย่างภาพหนึ่ง batch ก่อนฝึก |
| 3.4 | `cache()` + `prefetch(AUTOTUNE)` - เตรียม batch ถัดไปล่วงหน้าระหว่าง GPU ฝึก batch ปัจจุบัน |
| 3.5 | **Feature extraction** - โหลด EfficientNetV2B0 (`include_top=False`), ตั้ง `base.trainable = False`, ต่อ `GlobalAveragePooling2D` → `Dense(3, softmax)` ของเราเอง |
| 3.6 | ฝึก 5 epoch |
| 3.7 | **Fine-tuning** - `base.trainable = True` แล้วตรึงกลับทุกชั้นยกเว้น 20 ชั้นท้าย, compile ใหม่ด้วย `learning_rate=1e-5`, ฝึกอีก 5 epoch |
| 3.8 | เทียบ validation accuracy สูงสุดของสองวิธี |

**จุดที่ให้สังเกต:**
- EfficientNet มี normalization อยู่ภายในตัวแล้ว จึงป้อนค่าพิกเซล 0–255 ได้โดยตรง **ไม่ต้องหาร 255** (ต่างจากส่วนที่ 1 และ 2) - ถ้าเผลอหาร 255 ความแม่นจะตกลงอย่างชัดเจน
- ใน `summary()` ตอน feature extraction: **Total params 5,923,155 แต่ Trainable params เพียง 3,843** (แค่ชั้น `Dense(3)` ที่เราเพิ่ม = 1280×3 + 3) ส่วนที่เหลือคือโมเดลเดิมที่ถูกตรึงไว้ - นี่คือเหตุผลที่ฝึกได้เร็วและใช้ข้อมูลน้อย
- ความแม่นสูงตั้งแต่ epoch แรก ๆ ทั้งที่ข้อมูลมีน้อยมาก
- **ตอน fine-tuning ต้องใช้ learning rate ต่ำมาก (1e-5)** เพื่อไม่ให้ความรู้เดิมที่ดีอยู่แล้วเสียหาย และต้อง `compile()` ใหม่ทุกครั้งหลังเปลี่ยนค่า `trainable` มิฉะนั้น Keras จะยังใช้ค่าเดิมที่ compile ไว้
- `base` มีทั้งหมด 270 ชั้น การปลดล็อก 20 ชั้นท้ายจึงเท่ากับเปิดให้ปรับได้ราว 7% ของโมเดล
- โน้ตบุ๊กใช้ `test_ds` เป็น `validation_data` ตรง ๆ เพื่อความเรียบง่ายในห้องเรียน ในงานจริงควรแยก validation set ออกจาก test set ต่างหาก เพราะการเลือกโมเดลจากชุดที่ใช้วัดผลทำให้ตัวเลขดูดีเกินจริง

### ส่วนที่ 4 - สรุปเปรียบเทียบ (เซลล์ 55–57)

พิมพ์ตารางรวมผลทั้งวัน - MLP / CNN / Feature extraction / Fine-tuning พร้อม accuracy และจำนวนพารามิเตอร์

> ในตารางนี้ค่า accuracy ของ MLP กับ CNN มาจาก **test set** ของ Fashion-MNIST ส่วนของ transfer learning สองแถวล่างเป็นค่า **validation accuracy สูงสุด** ซึ่งวัดคนละแบบ จึงเทียบกันตรง ๆ ข้ามงานไม่ได้ ให้เทียบภายในงานเดียวกันเท่านั้น (MLP กับ CNN, และ feature extraction กับ fine-tuning)

**ข้อสังเกตที่คาดว่าจะได้เห็น**

1. CNN แม่นกว่า MLP บนงานเดียวกัน ทั้งที่พารามิเตอร์ต่างกันไม่มาก
2. Transfer learning ให้ความแม่นสูงมากบนข้อมูลอาหารที่มีน้อย เพราะยืมความรู้จาก ImageNet มา
3. Fine-tuning มักให้ผลดีกว่า feature extraction เล็กน้อย - แต่ด้วย test set เพียง 75 ภาพ ผลต่างเล็ก ๆ อาจเป็นแค่ความบังเอิญ ไม่ต้องแปลกใจถ้าบางรอบออกมาเท่ากันหรือแย่กว่า

**บทสรุปของวัน:** workflow การฝึกโมเดลคือ **สร้าง → compile → fit** เสมอ สิ่งที่เปลี่ยนคือโครงสร้างโมเดลและวิธีเตรียมข้อมูล และในงานจริงเรามักเริ่มจากโมเดลสำเร็จรูปแทนการฝึกใหม่จากศูนย์

### 5.2 ต่างจาก `Day1_Afternoon.ipynb` ส่วนที่ 3 อย่างไร

ทั้งสองที่ทำ transfer learning เหมือนกัน แต่เปลี่ยนของเกือบทุกชิ้น จึงไม่ใช่งานซ้ำ

| | ช่วงบ่าย ส่วนที่ 3 | workshop-1 |
|---|---|---|
| ชุดข้อมูล | pizza / steak / sushi (3 คลาส, 300 ภาพ) | IP102 แมลง (20 คลาส, 9,970 ภาพ) |
| โมเดลฐาน | EfficientNetV2B0 อย่างเดียว | **เทียบ EfficientNetV2B0 กับ ResNet50V2** |
| ตัวเทียบ | ไม่มี | **baseline CNN ฝึกเองจากศูนย์** |
| Augmentation | ไม่มี | RandomFlip / Rotation / Zoom / Contrast |
| ปลดล็อกตอน fine-tune | 20 ชั้นท้าย | 30 ชั้นท้าย (+ ตรึง BatchNorm) |
| วัดผล | accuracy อย่างเดียว | confusion matrix + classification report + recall รายคลาส + ภาพที่ทายผิด |

**สี่อย่างที่โน้ตบุ๊กนี้เพิ่มเข้ามาและควรสังเกตเป็นพิเศษ**

1. **มี baseline ให้เทียบ** - ช่วงบ่ายบอกว่า transfer learning ได้ผลดี แต่ไม่มีตัวเทียบให้เห็นว่า "ดีกว่าอะไร" ที่นี่ฝึก CNN เองจากศูนย์ก่อน แล้วค่อยเอา transfer learning มาทับ
2. **เทียบ base model สองตัว** - งานเลยเปลี่ยนจาก "ใช้โมเดลที่กำหนดมา" เป็น "เลือกโมเดลจากหลักฐาน" โค้ดเขียนเป็นฟังก์ชันที่รับ config จึงเพิ่มโมเดลตัวที่สามได้ด้วยการเติม 4 บรรทัดใน `CONFIGS`
3. **ผูก `preprocess_input` ไว้กับ base model** - ใน `CONFIGS` แต่ละตัวมีฟังก์ชัน preprocess ของตัวเอง (EfficientNet เป็น `None` เพราะมี normalization ในตัว, ResNet50V2 ต้องเรียกเอง) ใส่ผิดตัวจะไม่มี error แต่ accuracy ตกโดยไม่รู้สาเหตุ
4. **ตรึง BatchNorm ตอน fine-tuning** - จุดนี้ช่วงบ่ายไม่ได้ทำ ถ้าปล่อยให้ BatchNorm ปรับตัวตอน fine-tune สถิติ mean/variance ที่สะสมมาจาก ImageNet จะเพี้ยน

### 5.4 จุดที่ให้สังเกต

- **Baseline จะได้ราว 20–30%** ซึ่งดีกว่าเดาสุ่ม (5% เพราะมี 20 คลาส) แต่ยังต่ำมาก ส่วน feature extraction ที่ฝึกพารามิเตอร์แค่ระดับ 25,000 ตัว กลับทำได้สูงกว่าหลายเท่าตั้งแต่ epoch แรก ๆ นี่คือแก่นของงานนี้
- **โมเดลใหญ่ไม่ได้แปลว่าดีกว่าเสมอ** ResNet50V2 มีพารามิเตอร์มากกว่า EfficientNetV2B0 ราวสี่เท่า แต่ส่วนต่างของความแม่นมักไม่ได้มากตามขนาด
- **ความไม่สมดุลของคลาสมีผลจริง** คลาสใหญ่สุดกับเล็กสุดต่างกันเกิน 10 เท่า โมเดลจะเอนไปทางคลาสใหญ่ จึงต้องดู confusion matrix แบบเปอร์เซ็นต์ต่อแถวและดู recall รายคลาสประกอบ ไม่ใช่ดู accuracy รวมอย่างเดียว
- **20 คลาสทำให้ตารางมี 400 ช่อง** เซลล์ confusion matrix จึงวาดด้วยสีเป็นหลัก แล้วเขียนตัวเลขเฉพาะช่องที่มีค่าตั้งแต่ 5% ขึ้นไป
- **accuracy ที่ได้จะดูต่ำเมื่อเทียบกับงานจำแนกดอกไม้** แต่ไม่ได้แปลว่าโมเดลแย่ - งานวิจัยที่ใช้ IP102 เต็มชุด 102 คลาสก็ทำได้ราว 60–75% เท่านั้น

### 5.5 ข้อควรระวัง

- **ต้องใช้ GPU** ข้อมูลหมื่นภาพกับ ResNet50V2 บน CPU จะใช้เวลาหลายชั่วโมง บน Colab GPU (T4) ราว 25–40 นาที ตอนลองครั้งแรกให้ลด `EPOCHS_FE` กับ `EPOCHS_FT` เหลืออย่างละ 3 ก่อน
- **ต้องมีพื้นที่ว่างราว 2GB** วัดจากเครื่องที่โหลดจริงแล้ว: zip 641MB + ที่แตกและจัดโฟลเดอร์แล้วอีกราว 1.1GB (รวมทั้งภาพต้นฉบับและสำเนาใน `by_class`) รวมประมาณ **1.8GB** ใน `~/.keras/datasets/` ถ้าพื้นที่ตึง ลบ `MD-IP102.zip` ทิ้งได้หลังแตกไฟล์สำเร็จแล้ว
- **`cache()` กิน RAM ราว 6GB** ถ้าเครื่องไม่พอให้เปลี่ยนเป็น `cache("cache.tf")` เพื่อ cache ลงดิสก์แทน
- โน้ตบุ๊กใช้ `val_ds` เป็นทั้ง validation และชุดวัดผลสุดท้าย เหมือนช่วงบ่าย - สะดวกในห้องเรียนแต่ทำให้ตัวเลขดูดีเกินจริง ถ้าจะทำให้ถูกต้องควรแบ่ง test set ออกมาต่างหาก
- เซลล์ `run()` แก้ `base.trainable` ของอ็อบเจกต์เดิมทับ ถ้ารันข้ามลำดับหรือรันซ้ำจะได้สถานะที่ไม่ตรงกับที่อธิบายไว้ - ไม่แน่ใจเมื่อไรให้ Restart & Run All

## 8. ต่อยอดจาก `workshop-1`

เซลล์สุดท้ายของโน้ตบุ๊กเสนอทางต่อไว้ เรียงจากง่ายไปยาก

1. **ใส่ `class_weight`** ชดเชยคลาสที่ไม่สมดุล - สำคัญที่สุดกับชุดนี้ เพราะคลาสใหญ่สุดกับเล็กสุดต่างกันเกิน 10 เท่า
2. **ใช้ `EarlyStopping`** แทนการกำหนด epoch ตายตัว จะได้ไม่ต้องเดาว่า 10 epoch พอหรือไม่
3. **เพิ่ม base model ตัวที่สาม** เช่น `ConvNeXtTiny` หรือ `EfficientNetV2S` ใน `CONFIGS` (อย่าลืม `preprocess` ให้ตรง)
4. **ปรับ `fine_tune_layers`** ดูว่าปลดล็อกกี่ชั้นแล้วได้ผลดีที่สุด
5. **เพิ่ม `N_CLASSES`** เป็น 50 หรือใช้ครบ 97 คลาส แล้วดูว่า accuracy ตกไปเท่าไร (อย่าลืมลบ `by_class` ก่อน)
